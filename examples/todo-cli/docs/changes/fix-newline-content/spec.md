# 变更规格：修复——内容包含换行符时列表输出串行

> 轻量级路径产物（模板：lite-spec-template.md）。缺陷由交付后实际使用发现，真实复现：`todo add "第一行\n第二行"` 后 `list` 输出被拆成两行，第二条无 ID 无标记，"一条待办一行"的显示契约被破坏。

## 1. 变更描述

- **一句话**：修复——待办内容包含换行符（`\n` / `\r`）时，`add` 与 `list` 的输出串行，破坏 FR-2 的逐行显示格式。
- **问题来源**：交付后使用反馈：复制多行文本粘贴为待办内容后列表错乱。

## 2. 影响范围

| 项 | 内容 |
|----|------|
| 涉及模块/文件 | `todo/core.py`（`add` 增加一项校验）+ 测试文件；`cli.py`、`storage.py`、`models.py` 不动 |
| 是否新增接口/表结构 | 否（数据结构、JSON 格式、退出码约定均不变） |
| 连带影响 | 无——历史数据中已存的多行内容不做迁移，渲染保持原样（见"明确不做"） |

## 3. 验收标准（可自动验证）

| 编号 | 验收标准 | 验证方式 |
|------|----------|----------|
| A-1 | `todo add "第一行\n第二行"` 退出码 2，stderr 提示含"换行"，数据文件不写入新条目 | 子进程真实调用，看 stdout/stderr 与退出码 |
| A-2 | 内容含 `\r` 同样拒绝，退出码 2 | 同上 |
| A-3 | 单行正常内容的添加与列表不受影响（回归，沿用主用例 TC-18/TC-21） | 全量回归既有 42 个单元测试 |
| A-4 | 修复前合法保存的多行待办数据文件：`list` 退出码 0、不崩溃（兼容不迁移） | 手工构造历史数据文件后子进程调用 |

## 4. 实现要点

1. `core.TodoApp.add` 在空内容校验之后增加换行符校验，命中即抛 `TodoError`（exit_code=2，走既有错误通道，CLI 层零改动）
2. 校验覆盖 `\n` 与 `\r`（跨平台粘贴两种行尾都会出现）
3. 不在渲染层做截断或替换——在入口拒绝比在出口美化诚实

## 5. 明确不做

- 历史数据迁移（已存的多行条目保持原样渲染）
- 内容中全角/半角空格的清洗（校验用 `strip` 判空，但存储保留原文，本变更不扩大范围）
- Tab、其他控制字符的处理
