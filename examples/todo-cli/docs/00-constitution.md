# 项目约束（Constitution）

> 产生于阶段 0。技术栈边界、规范要点、质量底线——设计（02-design.md）与编码（阶段 3）必须逐条遵守；要改约束先改本文件。

本示例无既有工程可继承约束，由用户与 AI 在启动时约定如下：

## 技术栈边界

- **语言**：Python 3.10+（仅标准库，**零第三方依赖**）——示例项目必须任何机器开箱可跑，不为演示引入 pip 安装步骤
- **数据存储**：单文件 JSON（`~/.todo-cli.json`），通过 `TODO_FILE` 环境变量可覆盖——CLI 工具不需要数据库
- **测试框架**：`unittest`（标准库自带）；构建/语法检查用 `python -m compileall`
- **禁止**：requests、click 等一切第三方库；网络访问

## 规范要点

- 模块按职责分层：`models.py`（数据结构）→ `storage.py`（持久化）→ `core.py`（业务）→ `cli.py`（命令行入口），依赖只能单向（右不依赖左）
- 错误处理：用户可见错误统一走 `TodoError`，CLI 层捕获后转人类可读消息 + 非零退出码，不允许裸抛 traceback
- 退出码约定：`0` 成功；`1` 业务错误（找不到待办等）；`2` 用法错误（参数不合法）
- 所有用户可见文案为中文；代码命名、注释遵循 PEP 8

## 质量底线

- 每个公共类/公共方法至少有正常路径、边界条件、异常场景三类单元测试
- 全部单元测试通过（`python -m unittest` 退出码 0）才允许进入阶段 4
- 非零退出码的路径必须有测试断言覆盖
- 构建检查（`python -m compileall`）零错误零警告
