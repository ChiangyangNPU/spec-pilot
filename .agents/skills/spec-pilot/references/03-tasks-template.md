# 任务清单模板

> 使用说明：以 docs/02-design.md 为依据拆解。任务按执行顺序排列，粒度标准：一个任务一次提交、可独立验证；预计超过半天工作量或横跨多个模块的继续拆。

## 任务清单

| # | 任务 | 目标（做什么） | 涉及模块 | 完成判据（怎么算做完） | 预估工时 | 实际工时 | 依赖 | 状态 |
|---|------|----------------|----------|------------------------|----------|----------|------|------|
| T1 | | | | 可验证的判据（如"接口返回正确数据且单测通过"） | 如 0.5 天 | 完成时回填 | 无 | ☐ |
| T2 | | | | | | | T1 | ☐ |
| T3 | | | | | | | T2 | ☐ |

要求：

- **每个任务必须有完成判据**，且判据可真实验证（运行命令、调用接口能确认），不允许"完成基本功能"这类模糊表述
- 完成判据应能对应到一条或多条测试用例（04-test-cases.md 的用例 ID）
- **预估工时在拆解时给出、实际工时在任务完成勾选时回填**——两者对照是验收复盘"估算偏差"的唯一数据来源，缺了实际值偏差就无从度量；只用于复盘校准，不作为赶工承诺
- 基础设施类任务（项目初始化、依赖安装、数据库迁移）也列出，不遗漏

## 产出物自检

> 通用规则"对照模板逐项自检"的落点；全部勾选后才冻结测试用例。

- [ ] 每个任务有可真实验证的完成判据，且能对应到测试用例 ID
- [ ] 每个任务有预估工时（验收复盘时与实际耗时对照，供 lessons 记录估算偏差）
- [ ] 任务与需求对照无遗漏（FR/NFR 全部被任务覆盖）
- [ ] 粒度合格：一个任务一次提交、可独立验证、预计不超过半天
- [ ] 基础设施类任务（初始化、依赖、迁移）未遗漏
