# 测试报告模板

> 使用说明：每轮测试执行后更新本文件。测试的唯一依据是冻结的 docs/04-test-cases.md。

## 1. 执行概要

- **轮次**：第 N 轮
- **触发原因**：首次执行 / 修复缺陷后回归
- **用例总数**：X ｜ 通过：Y ｜ 失败：Z ｜ 阻塞：W
- **通过率口径**：通过率 = Y / (Y+Z)，**BLOCKED 不计入分母也不计入通过**——它是"没跑成"，既不是通过也不是失败
- **结论**：全部通过，可交付 / 存在失败用例，进入修复循环（第 N/5 轮）/ 存在 BLOCKED 用例，需补环境补跑或用户决策（未处理前不得交付）

## 2. 单元测试结果

| 指标 | 结果 |
|------|------|
| 测试命令 | （如 `npm test` / `pytest`） |
| 构建 / Lint / 静态检查 | （命令与退出码；**未真实执行的必须写明原因**，不允许静默留空——阶段 3 的客观裁判要求在此留痕） |
| 用例总数 / 通过 / 失败 | |
| 代码行覆盖率 | （无覆盖率工具时可填写替代口径并注明原因，如"未测量：零依赖约束不引入 coverage 工具，以 04 用例矩阵覆盖代替"） |

## 3. 功能用例执行结果

结果取值：✅ 通过 / ❌ 失败（关联缺陷编号）/ 🚫 BLOCKED（环境前置不满足、无法执行，详见第 4 节）。

| 用例 ID | 来源需求 | 结果 | 实际结果/缺陷编号 |
|---------|----------|------|-------------------|
| TC-01 | FR-1 | ✅/❌/🚫 | |
| TC-02 | FR-2 | ✅/❌/🚫 | |

> 严禁以静态阅读代码"推断应该通过"把无法执行的用例记为 ✅——没真实跑出结果的只能是 🚫。

## 4. 阻塞用例清单（BLOCKED）

> 环境前置不满足而无法执行的用例在此登记。BLOCKED 不触发缺陷修复循环，但交付前必须逐条解除（补跑为真实 ✅/❌）或经用户明确接受。

| 用例 ID | 受影响需求 | 阻塞原因（缺什么环境/依赖/授权） | 解除条件 | 处置（补跑结果 / 用户接受） |
|---------|------------|----------------------------------|----------|------------------------------|
| | | 如：本机无 Python 运行时，无法执行 CLI 用例 | 安装 Python 3.10+ 后重跑 | |

## 8. 产出物自检

> 通用规则"对照模板逐项自检"的落点；全部勾选后才进入收敛核对与交付。

- [ ] 冻结用例全部执行，无静默跳过；本环境无法验证的标注"未验证 + 原因"
- [ ] 无法执行的用例一律记为 🚫 BLOCKED 并填入第 4 节（原因、解除条件、受影响需求），没有"推断通过"
- [ ] 交付前无未处理的 BLOCKED：已补跑出真实结果，或用户已明确接受该范围未验证
- [ ] 构建/Lint/静态检查结果行已填（或注明未执行原因）
- [ ] 每条 NFR 已验证或标注未验证原因
- [ ] 缺陷每轮回填了根因/修复策略；趋势表可判断收敛方向
- [ ] 报告结论与用例执行结果一致（有失败或未处理 BLOCKED 不得写"可交付"）
