# 编码自检清单

> 使用说明：阶段 3 编码开始前阅读一遍，每个模块完成后逐项自检。全部通过再进入阶段 4 测试。本文件是编码阶段的过程规范，不是阶段产物模板，故不带产物编号。

## 1. 符合设计

- [ ] 实现与 `docs/02-design.md` 一致（模块职责、接口签名、数据结构）
- [ ] 偏离设计的改动已先更新设计文档并追加变更记录，再改代码
- [ ] 没有实现需求范围之外的功能（防顺手加戏）

## 2. 正确性

- [ ] 正常路径有单元测试覆盖
- [ ] 边界条件已处理并测试（空输入、空列表、0、负数、最大值、超长字符串）
- [ ] 异常场景已处理并测试（网络失败、文件不存在、非法参数、并发冲突）
- [ ] 错误信息可定位（带上下文，不吞异常、不返回裸 "error"）
- [ ] 依赖的外部调用有失败兜底（超时、重试或明确失败）
- [ ] **测试可重复、无 flaky**：不依赖真实 sleep/时序竞态判断结果，时间源与随机源可注入或固定种子，测试数据每轮可重置、不依赖执行顺序与上一轮残留——偶发失败会污染"以退出码为准"的客观裁判（真失败被当偶发放过、偶发失败误伤可信度）

## 3. 可读性与规范

- [ ] 命名准确表达意图，无无意义的缩写
- [ ] 注释只解释"为什么"，不复述代码做了什么
- [ ] 无复制粘贴的重复代码，公共逻辑已提取
- [ ] 函数短小、单一职责，嵌套不超过 3 层
- [ ] 遵循所选语言/框架的官方风格指南，通过 Lint 检查

## 4. 安全

- [ ] 外部输入（用户输入、请求参数、文件内容）已校验，不直接信任
- [ ] 数据库操作使用参数化查询，无字符串拼接 SQL
- [ ] 无硬编码的密钥、密码、Token（用配置或环境变量）
- [ ] 敏感信息（密码等）不进日志
- [ ] 依赖无已知高危漏洞（通过依赖审计检查）

## 5. 可维护性

- [ ] 魔法数字/字符串提取为具名常量
- [ ] 配置与代码分离（环境、端口、路径等不写死）
- [ ] 关键决策和复杂逻辑有简要说明（README 或代码注释）

## 6. 提交前检查

- [ ] 构建通过（真实运行构建命令）
- [ ] 全部单元测试通过（真实运行，看退出码）
- [ ] Lint / 静态检查通过，无未处理的警告
- [ ] 无调试残留（print/console.log、注释掉的死代码、临时文件）
